# MultiPoll Studio for Windows 0.5.1

Publisher account: **Wayan123**. License: **GPL-3.0-or-later**.

## Download and run

Open [the v0.5.1 GitHub Release](https://github.com/Wayan123/multipoll-studio/releases/tag/v0.5.1).
Download `MultiPollStudio-0.5.1-windows.zip`, extract it into a local Windows folder, and run
`MultiPollStudio.exe`. The ZIP includes the license, notices, release notes and a short getting-started guide.
The EXE is also available as a separate download. It requires .NET Framework 4.8 and does not need an installer
or administrator rights. The Python edition is source-only in this release and retains its own version.

**This EXE is not Authenticode-signed.** Windows can show an unknown-publisher or SmartScreen warning;
Smart App Control or organizational policy may block it. Do not disable security controls to run the program.
If your environment does not permit the binary, use the source/build instructions or wait for a signed build.
The GitHub publisher account is not an independently verified legal identity.

## Changes

- Purpose-grouped menus, `Poll Setup`, `Frame Console` and explicit display-format/byte-order names.
- Separate unit/function/interval and request/error/response-time status, with the full status in a tooltip.
- App-rendered screenshot gallery covering connection and polling setup, all six write-function dialogs,
  float writes, profiles, settings, diagnosis, tags, alarms, logging, Interpret As, workspaces, trend and traffic.
- UI smoke tests now use a GUID-suffixed registry key and audit files in the run's output directory.
  Cleanup does not delete another run's registry key.
- Application assembly/file version is `0.5.1.0`; product version is `0.5.1`.

Documents/workspaces remain schema version 1. Existing `.mpoll` display-format keys and Modbus protocol
semantics are unchanged. Frame Console lists require the header `MultiPoll Studio Frame List`;
back up older lists before changing their first line. Old OpenPoll settings are not imported automatically.

Built on 2026-10-30 with `openpoll-win/build.sh` and `openpoll-win/build.sh uitest`, using Visual Studio
Roslyn C# compiler `5.5.0-2.26208.13` on the authorized Windows/WSL host. Two existing CS0649 warnings concern
fields assigned by the test harness (`Ui.AutoAnswer` and `MainForm.AuditPath`); the builds succeeded.

Commands used the built Windows EXEs with `--selftest <simulator-host> 16520`,
`MultiPollStudioUiTest.exe <simulator-host> 16520 <unique-output>/main`,
`MultiPollStudioUiTest.exe devices 127.0.0.1 16530 <unique-output>/devices`, and
`MultiPollStudioUiTest.exe toolbar 127.0.0.1 16530 <unique-output>/toolbar`.
Protocol simulator: `tools/demo_slave.py`; device simulator: `tools/device_sim.py`.
All writes were to these owned simulators. COM26 and other physical devices were not accessed.

Screenshots use `DrawToBitmap` to render the actual application forms. They are not desktop recordings or
proof of device compatibility. The profile-folder row is masked in the profile-selection image for privacy.
The GIF remains an older screenshot slideshow. Native file/print dialogs and alarm-history message boxes
are not pictured. Printing and hardware commissioning were not tested.

Release was requested immediately by the owner on Friday afternoon; this is a downloadable desktop build,
not a production deployment. No hosted CI workflow exists: the evidence above is local verification, not a CI claim.

## Checksums and separate artifact signature

The validated `MultiPollStudio.exe` is 359,424 bytes, SHA-256:

```text
90d65a7a1b8c1d7fb5afef8e384c31f8f6c90fc2a0cff5bb991d816433d85915
```

The release includes `SHA256SUMS` for the downloadable payloads, `SHA256SUMS.sig`, `SIGNING-KEY.pub` and
`allowed_signers`. The detached signature uses the existing SSH signing key; no new GPG key is required.
**It is not an Authenticode signature and will not remove Windows warnings.**

For a downloaded EXE, use PowerShell and compare the hash with the value above or the release checksums:

```powershell
Get-FileHash .\MultiPollStudio.exe -Algorithm SHA256
```

To verify the checksum-file signature with OpenSSH in WSL/Linux, first compare the downloaded public key
fingerprint with this independently known value:

```text
SHA256:gIwYtW9UCRWuuhwknxIVXjyhOixqXikxg7P3u7FRmyw
```

```sh
ssh-keygen -lf SIGNING-KEY.pub
ssh-keygen -Y verify -f allowed_signers -I Wayan123 -n multipoll-release \
  -s SHA256SUMS.sig < SHA256SUMS
sha256sum -c SHA256SUMS
```

Download all listed payloads into the same directory before checking all entries. The public signing key is
also listed by [GitHub's public signing-key API](https://api.github.com/users/Wayan123/ssh_signing_keys).
A checksum alone detects differing bytes; trusting a signature also requires trusting the key's provenance.
The build manifest records source identities and tooling; it is not an independently reproduced-build or SLSA attestation.
